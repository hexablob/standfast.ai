# Design state — 2026-08-19

## Settled
- Name: Standfast, domain standfast.ai, npm scope `@standfast/*`, binary
  `standfast`. Renamed from PactAI on 2026-08-19. The old name inherited a
  collision it could never win: `pact` belongs to pact.io, the contract-testing
  tool, whose `@pact-foundation/pact` ran 662k npm downloads in the week ending
  2026-08-04 — same audience, so every branded search returned the wrong
  software. Standfast has no namesake in developer tooling: npm, PyPI,
  crates.io and the MCP registries all returned nothing for the word when it
  was chosen.
- Stack: see CLAUDE.md.
- MCP server built from mode-bearing tools rather than twenty-odd
  single-purpose ones — reason: per-session token cost and the quality of the
  agent's tool selection. The count is settled below, not here.
- Incremental extraction by section hash.
- Anti-hallucination by verbatim quote verification.
- Deduplication: cosine < 0.80 distinct, > 0.93 merge, LLM judge only in the
  intermediate band. Thresholds to be recalibrated on a real corpus.
- Retrieval: 4 candidate generators, RRF fusion k=60, cross-encoder reranker,
  assembly under budget with MMR λ≈0.7.
- License: AGPL-3.0-only for the server (`api`, `core`, `db`, `worker`),
  Apache-2.0 for what the user runs locally (`cli`, `mcp`, `sdk`). Copyleft
  where it protects against hosted reuse, permissive on the integration
  surface. See `NOTICE`.
- Tooling: Biome for lint and format, Vitest for tests, Drizzle + drizzle-kit
  for schema and migrations.
- Business model: open source first, paid hosted version later. The licence
  split already serves it. Two consequences worth holding onto: AGPL deters a
  competitor who *modifies* Standfast but not one who hosts it unchanged, and it
  obliges our own hosted version to publish its modifications — so hosted
  differentiates on operations and on bundled model spend, not on secret code.
- Contributions require a CLA (`CLA.md`), decided while there were zero outside
  contributors. It keeps open the option of a commercial licence for
  organisations whose policy forbids the AGPL, and adds an explicit patent
  grant. Reversible in one direction only: the right can go unused. Adopting it
  later would have meant chasing every past contributor for a signature.
- Validation stays Zod with `@hono/zod-openapi`, and Valibot was considered and
  declined. There is no `@hono/valibot-openapi`, so the swap would replace the
  first-party Hono integration with a community Standard Schema router and
  rewrite every route, not just every schema. Valibot's advantage is bundle
  size under tree-shaking, and nothing here pays for that: the server is Node,
  and the SDK is generated by `openapi-typescript`, which emits types and ships
  no runtime validator at all. Revisit only if a browser client appears.
- Postgres hosting: Neon. Database branching is worth real money when testing
  extraction migrations. Neon provides no auth, so authentication is ours:
  hashed, scoped API keys for the CLI and MCP clients. RLS keys on a
  transaction-scoped GUC rather than on a vendor's `auth.uid()`, which keeps
  the AGPL server self-hostable on any Postgres.
- Tenancy: `org_id` on every row from the first migration. A solo user is an
  org with one member, so phase 5 adds rows to `actors` instead of re-keying
  eight tables and rewriting every policy against live data.

- Reconciliation false-positive rate settled at **< 5%** as the phase-3 exit
  threshold, with the corpus and labelling procedure committed so it can be
  recomputed by someone who did not run it (`docs/12-evaluation.md`,
  `docs/14-roadmap.md`). It may be tightened, never loosened: a reconciler that
  cries wolf is worse than no reconciler, because it trains people to dismiss
  it.
- MCP catalogue settled in `docs/08-mcp-server.md`: six tools, not ten. The cap
  is a budget and four slots stay unspent. Tool descriptions are capped at
  1200 tokens, measured in CI. Document writing is absent on purpose — that is
  the sync daemon's job, and two write paths into the same source is two ways
  for it to disagree with itself. There is no ratify tool; the absence is the
  design.
- Client strategy: MCP is the cross-tool promise (Claude Code, Cursor, Codex,
  Gemini); Claude Code hooks add deterministic injection that MCP cannot,
  because MCP is pull and cold start needs push. Ships as a Claude Code plugin
  bundling both, and as a plain MCP server everywhere else.

## Open
- Default embedding model: OpenAI 3-large truncated to 1024 vs voyage-3.
- Reranking provider.
- Whether `status` folds into `context` as a mode, and whether `context` should
  accept a diff once reconciliation exists (`docs/08-mcp-server.md`).
- The outbound allowlist for model, embedding and reranking endpoints
  (`docs/13-threat-model.md`, *Egress*). Blocks phase 2.

## Next action

**Phase 0 is complete.** Schema with row-level security, API-key auth, CRUD,
the generated SDK, the `standfast` CLI, and the MCP server with its three phase-0
tools (`read`, `propose`, `status`). `docs/14-roadmap.md` lists the exit
criteria and each is checked in CI.

**Every design document is written.** `docs/03` through `docs/15` are settled
designs; none is a stub. What they describe is mostly *not built* — each
carries a status banner saying so, and names the files that hold whatever part
does exist today. Read the banner before inferring anything from the prose.

**Phase 1 is under way — extraction.** `docs/05-extraction.md` owns it, and
`docs/14-roadmap.md` splits it into 1a through 1d. Two defects phase 0 shipped
blocked all of it, and phase 1a closed both:

- `putDocument` deleted and re-inserted sections on every upload, which cascaded
  every atom projected from them. Bulk extraction on top of that would have
  destroyed ratified knowledge on each `doc push`. It now matches sections by
  hash and deletes only what the new body no longer yields.
- `createAtom` never read the section a quote claimed to come from, so
  provenance was asserted rather than verified. A `BEFORE INSERT OR UPDATE`
  trigger now runs the comparison on the write path.

Phase 1b then shipped the evaluation harness — before the first prompt, and
with no labels in it, because a human writes those blind. 1c is the queue and
the pipeline; 1d binds the models.

Three decisions must close before the phases that need them. The embedding
provider (phase 1) and the p95 latency figure for `context` (phase 2) are owned
by `docs/14-roadmap.md`. The outbound allowlist in `docs/13-threat-model.md`'s
*Egress* section is scheduled there for phase 2, but 1d opens the first
outbound socket in this repository — the roadmap moves it to 1d and explains
why.

Publication to the MCP registries waits until reconciliation works. A server
that serves almost nothing spends a first impression that cannot be spent
twice.
